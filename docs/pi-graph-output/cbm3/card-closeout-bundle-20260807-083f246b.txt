8. Architecture and Design Decisions
================================================================================
  - store root = ~/.autoloop/memory/（no pre-existing memory state root; env override AUTOLOOP_MEMORY_STATE_ROOT for test isolation; never inside a git worktree; tests use isolated tmpdirs）
  - store identity = sha256(canonical({schema, schemaVersion, journalGenesisDigest, backend})) — fixed for the contract, identical across rebuilds; never path/mtime/sqlite internals
  - explicitImport is the ONLY write path: full CBM-2 validation（schema/identity/secret scan/scope/evidence/journal）→ journal append（fsync）→ sqlite upsert → FTS; idempotent（UNIQUE(recordId) and UNIQUE(logical_key,content_hash)）; automatic write-back is CBM-4
  - journal-first durability + parity: open validates the full chain（corrupt middle / dup / gap → MEMORY_STORE_INVALID fail-closed）; missing sqlite + valid journal → lossless rebuild; sqlite⊆journal（crash between append and insert）→ lossless rebuild; sqlite with records absent from the journal → MEMORY_STORE_INVALID（cannot reconcile without data loss）
  - query contract autoloop.memory-query/v1: repository REQUIRED hex64; worktree/commit/tree/graphRunId/task optional; recordTypes/scope filters; trustFloor default VERIFIED（production trusted context ≥ VERIFIED; RAW/UNVERIFIED never enter trusted context）; validityPolicy CURRENT|INCLUDE_STALE|ALL; conflictPolicy SURFACE only; unknown fields/enums/malformed/oversized → fail closed
  - eligibility pipeline: repository hard boundary → worktree isolation → scope compatibility → trust floor → validity（CURRENT default; STALE/INVALIDATED/TOMBSTONED excluded; CONFLICTED surfaced, never selected）→ security/schema light re-validation（identity recompute + secret scan; no evidence file IO at query time）; tree-baseline staleness（scope.tree ≠ query tree → STALE for this context）
  - deterministic ranking tuple（documented + test-frozen）: 1 identityMatch（2 explicit recordId / 1 exact logicalKey）→ 2 scopeSpecificity（3 path-pinned / 2 symbol-pinned / 1 tree-pinned）→ 3 trustRank → 4 relationshipApplicability（identity-selected record's relationship graph）→ 5 lexicalMatchClass（deterministic term count — never bm25）→ 6 recordId ascending（stable tie-break）
  - FTS5 pinned tokenizer（unicode61 remove_diacritics 0, CBM-2）used ONLY for lexical candidate generation（binary in/out）; bm25/rowid/implicit ordering NEVER enter ranking or digest; every SQL has explicit deterministic ORDER BY; SQL candidate prefilter（repo/worktree/trust/validity/type/tree/graphRun/task in parameterized WHERE）avoids full-table serialization per query
  - conflict surfacing: two+ CURRENT records sharing logicalKey with ≥2 contentHash → conflictGroup（records excluded from selection, never merged / never 'choose first/newest/highest score'）; CONFLICTED-validity and conflict-table records surfaced with reason; relationships（DERIVED_FROM/VERIFIES/REVIEWS/SUPERSEDES/INVALIDATES/CONFLICTS_WITH/APPLIES_TO/PRODUCED_BY）preserved as applicable provenance per selected record
  - storeSnapshotDigest = sha256(canonical({records by recordId: recordId/logicalKey/contentHash/recordType/trust/validityStatus/scope + inConflictTable; relationships by relationshipId; conflicts by group})) — excludes rowid/WAL/mtime/absolute path/FTS score/latency; insertion-order invariant; rebuild invariant
  - retrievalDigest = sha256(canonical({queryIdentity, context, storeSnapshotDigest, selectedRecordIds in order, conflictGroups, excludedSummary, truncated, limits})) — same snapshot + same query ⇒ same digest（repeat/restart/rebuild/insertion-order proven）
  - Graph read-only integration: runColimaGraph({memory:{provider}}) resolves repo/worktree/tree identity → retrieval → structured autoloop.memory-context/v1（kind MEMORY_CONTEXT_DATA + authorityBoundary; memory is DATA, never instructions, never overrides Controller/governance）→ attached to result/nodes/phase.runtime and carried in sub-agent envelopes（executor/reviewer context）; missing store → EMPTY_MEMORY（graph continues）; corrupt store → HOLD/MEMORY_STORE_INVALID（fail closed, before any colima work）; scheduler/writer-lease/mutation/review/repair/commit authority untouched
  - limits: maxRecords default 50（1..1000）, maxBytes default 64KiB（1..256KiB）; truncation applies AFTER deterministic ranking in stable order（never serialisation timing）; result exposes counts/byteCount/truncated/excludedSummary
  - performance probe（10,000 synthetic records, isolated tmpdir; scripts/cbm3-memory-probe.mjs）: import 47.3s（211 rec/s, journal fsync per import — not the hot path）; store open 1.68s（incl. journal↔sqlite parity verify）; snapshot digest 72ms; exact recordId lookup <1ms; path+symbol lookup 177ms; FTS candidate query 325ms; deterministic retrieval 312ms（37 selected, truncated at limits）; repeat query deterministic; RSS 76MiB after import → 495MiB after first heavy query（plateau — allocator retention, not per-query growth）; open parity ok. Full JSON in docs/pi-graph-output/cbm3/cbm3-memory-probe-20260807-evidence.json
