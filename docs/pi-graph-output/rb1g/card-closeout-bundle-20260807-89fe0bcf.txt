8. Architecture and Design Decisions
================================================================================
  - REPAIR (external finding): markBundleDelivered / --record-delivery removed — sender-side delivery confirmation was not a receiver acknowledgment
  - the external verdict IS the receipt: applyExternalReviewVerdict binds CURRENT bundle identity+sha256 + reviewer identity + reviewedAt and thereby proves RECEIVED + REVIEWED
  - execution side records at most delivery.attempted (DELIVERY_ATTEMPTED) — informational only, never changes status, never contributes to completion
  - initial closeout status AWAITING_EXTERNAL_REVIEW; AWAITING_BUNDLE_DELIVERY only when the environment cannot hand the artifact over
  - repair supersede: new bundle gets a NEW identity (supersedes bound into reviewBundleIdentity), new sha256, explicit SUPERSEDES_* lines, old artifact retained, re-reviewed via a fresh verdict
  - REPAIR_BUDGET_USED = repair iterations CONSUMED (REPAIR-status attempts only); the final PASS attempt is not a repair — USED <= MAX invariant enforced by the validator (over-budget bundle rejected)
  - delivery record of a repair generation carries its SUPERSEDES binding parsed from the bundle's own section 14 (single source of truth); identity-without-sha / malformed bindings fail closed, and readExternalReviewDeliveryRecord rejects malformed supersedes
  - one card -> one complete review bundle -> reviewer receives + reviews the actual content -> verdict (PASS/REPAIR/HOLD) -> card external review complete only on PASS bound to the current bundle
