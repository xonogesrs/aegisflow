A. ROOT CAUSE（PROVEN, NOT ASSUMED）
================================================================================
Why the user kept receiving the same 413ab9ac bundle after every new work item:

1. The controller/harness-facing delivery/attachment step dereferences the
   FIXED external-review surface Current/ as the "current review bundle"
   （currentReviewDelivery / --export-for-card / AGENTS.md
   AUTHORITATIVE_SOURCE_FIRST）. Current/ is a SINGLE slot that holds an
   unresolved review — it is the authority for "what needs a verdict NOW",
   NOT a latest-report feed.
2. There was NO human-facing "latest completed work report" artifact at all.
   Queue/latest.json is navigation-only metadata（no report bytes, never
   touched by operator closeouts）; operator/non-review closeouts
   （runStateDrivenCloseout with requiresReview !== true）return
   closeout_not_required and publish nothing user-facing.
3. So every retrieval returned the Current occupant: 413ab9ac,
   GENERATED_AT 2026-08-16T16:38:25.140Z, AWAITING_EXTERNAL_REVIEW — forever.

Current ≠ latest report. The fix separates them.
