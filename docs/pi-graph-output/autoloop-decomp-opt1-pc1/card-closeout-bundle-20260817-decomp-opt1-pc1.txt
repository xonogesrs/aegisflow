1. WHAT WAS BUILT
--------------------------------------------------------------------------------
Single authoritative Parent/Run inheritance artifact + deterministic child
inheritance, per the frozen design (§8 A+B+D+E) extended with CBM-first
retrieval (card §C/§S).

New modules:
  src/v2/decomposition-inheritance.mjs          — pure core: manifest build/
    verify（content-addressed, deterministic digest, wall-clock excluded）,
    fact taxonomy F1–F6, three-way disposition engine（REUSE/REVALIDATE/
    RECOMPUTE + HOLD）, per-fact invalidation evaluation, Child Execution
    Packet builder, F3A/F3B baseline projection, per-child F3A guard
    （single `git rev-parse HEAD`）, telemetry shapes.
  src/memory/inheritance-cbm.mjs                — CBM-first retrieval: governed
    write-back of the manifest through the EXISTING write-back gate
    （UNVERIFIED, writer origin — no self-promotion）, deterministic
    tree-bound query（HIT/STALE/CONFLICT/CORRUPT/MISS）, per-child evidence-
    ref resolution.

Wired (opt-in `inheritance` on runExecutionOrchestrator; durable +
production paths enable it by default):
  src/v2/execution-orchestrator.mjs             — manifest resolved ONCE per
    run（CBM-first: HIT → reuse by identity; else bounded source build）;
    per child: F3A guard → dispositions → packet → taskCard.inheritedBaseline
    → verification layering（read-only phases skip the redundant process）;
    telemetry in result.inheritance.
  src/lifecycle-runner.mjs                      — evidence builder consumes the
    inherited baseline instead of re-collecting 9 git observations/child.
  src/v2/harness-evidence.mjs                   — guard command recorded;
    repository_baseline carries the explicit inheritance marker
    （no_per_child_freshness_claim — R1-C）.
  src/v2/review-evidence.mjs                    — F3A head/tree by reference
    （drops 2 git spawns/child; gate semantics unchanged）.
  src/v2/system-delta.mjs                       — F3A by reference for the
    shared-repository path; isolated writer worktrees still observe their
    own identity（child-local, MFRESH）.
  src/v2/durable-execution.mjs                  — orchestrator inheritance
    config（frozen inputFingerprint + repo fingerprint）; manifest persisted
    as durable artifact; resume re-derives + compares digest
    （DECOMPOSITION_INHERITANCE_IDENTITY_DRIFT fail-closed）; verified
    manifest reused on resume.
  src/v2/durable-graph.mjs                      — same for the production
    graph path（run + resume）.
  src/runtime/colima-graph-runner.mjs           — forwards `inheritance`,
    exposes result.inheritance.

  - redundant read-only verification process（RC6） — verification layering:
    writer/verification-flagged phases only.
NOT removed: child-local scope baseline, post-mutation capture, system
delta, harness evidence child-local block, review bundle, executor/reviewer
calls, journal/checkpoint writes, containment checks（MFRESH by design）.

7. CBM MATERIAL USE（§S — not just metrics）
--------------------------------------------------------------------------------
CBM answered real retrieval questions with verified identities:
  - "known parent context" — manifest record（repository + parentCardId +
    tree-bound）→ HIT → reuse without rebuild（dogfood r2/r4）.
  - "known dependency / drift" — tree binding → STALE on committed
    dependency change → rebuild（dogfood r3）.
  - "known evidence location" — per-child evidence-ref records resolved by
    scope path（queryChildEvidenceRefs）.
  - "known repository identity" — F3A digest verification before reuse.
CBM_HIT_COUNT = 0 was never observed; the write-back path works through the
governed gate（origin=writer, UNVERIFIED, evidence-ref=manifestSha256）.
A pre-existing query-classification defect（two CURRENT records for
different trees misread as CONFLICT）was fixed（tree-bound freshness）.

9. DESIGN DELTA vs FROZEN INVENTORY
--------------------------------------------------------------------------------
The frozen design inventory excluded CBM（"no CBM dependency"）. This card
（DECOMP-OPT1-PC1）explicitly requires CBM-first retrieval（§C/§S）; the
implementation adds the CBM layer WITHOUT weakening any frozen authority:
retrieval is identity-verified, write-back goes through the existing
governed gate, and a live/CBM conflict resolves to the live authority with
the CBM record surfaced. Everything else follows the frozen §7/§8 contract
（manifest + packet + F3A binding + verification layering + disposition
recording + telemetry）.
