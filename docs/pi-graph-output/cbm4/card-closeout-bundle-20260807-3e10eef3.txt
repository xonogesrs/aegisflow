8. Architecture and Design Decisions
================================================================================
  - write-back source map（autoloop.memory-writeback-source-map/v1, src/memory/writeback/source-map.mjs）: every Graph data source tagged source / authority / trustCeiling / requiredEvidence / allowedRecordType / allowedScope / deterministic / failureSemantics / writebackPermitted. Summary: 11 sources = 8 write-back-permitted（writer/executor self-claims and DECISION are NOT）
  - candidate contract autoloop.memory-writeback-candidate/v1: candidateId = sha256(canonical({schema, graphRunId, originatingNode, sourceResultIdentity, proposedRecordType, proposedIdentity, lifecycleIntent})) — NEVER timestamp/rowid/mtime/order/stdout; CONFIRMED is never an automatic intent; evidence references required
  - trust rules（card stage 4）: writer/executor propose（ceiling UNVERIFIED — no self-promotion）; verifier-backed facts reach VERIFIED（verifier-bound evidence identity required）; independent reviewer PASS + zero blocking findings + verifiable identity reach REVIEWED; CONFIRMED reserved for Controller（never auto-generated）; skip-level promotion fails closed
  - write-back gate（card stage 5）: candidate → schema/identity → authority/trust ceiling → evidence binding → scope isolation（cross-repo/cross-worktree rejected）→ security scan → conflict analysis → lifecycle intent → journal-first explicitImport → telemetry → structured status（WRITEBACK_ACCEPTED / REJECTED / CONFLICT / DUPLICATE / STORE_INVALID / EVIDENCE_INVALID / AUTHORITY_INSUFFICIENT）; any failure never writes partially
  - idempotency / crash safety（card stage 6）: recordId excludes timestamps（deterministic source timestamps; fixed epoch when absent — wall-clock now would break retry identity）; explicitImport idempotent（recordId OR (logical_key, content_hash)）; journal-first lifecycle（LIFECYCLE_EVENT journaled before sqlite; crash between → lossless rebuild）; repeated closeout / duplicated delivery → DUPLICATE, no duplicate trusted record
  - conflict / supersede / invalidate（card stage 7）: same logicalKey + contentHash → idempotent DUPLICATE; different contentHash → CONFLICT surfaced（never newest/highest/overwrite/merge）; SUPERSEDE/INVALIDATE only with evidence-bound lifecycle intent（relationship + evidence binding required; SUPERSEDED validity maps to INVALIDATED with the SUPERSEDES relationship preserving lineage）
  - staleness（card stage 8）: tree/path-bound CODE memory marked STALE（MARKED_STALE lifecycle, SYSTEM_DERIVED authority, evidence = new tree）when the baseline tree no longer holds — never served as current truth; execution memory keeps historical provenance without claiming current code truth
  - security（card stage 9）: CBM-2/3 contract extended — secrets/credentials/prompts/responses/stdout/stderr/blobs rejected before journal append; hostile text is DATA only; memory content can never modify system/controller/scheduler/permissions/review authority
  - COST-1 telemetry（card stage 10）: additive memory.writeback event type（counters + identities + digests ONLY; never memory content）; recorded from the FIRST production write-back; token/tool usage keeps honest-unknown semantics
  - Graph integration（card stage 13）: OPT-IN writeback param on runColimaGraph; runs AFTER the graph result + closeout gate + telemetry are final（passive side effect — failures never change the graph outcome）; EXECUTION memory always derived from the final verdict; CODE memory only from independent-review-PASS writer nodes with verifier/reviewer evidence identity; HOLD graphs record execution history only; writer self-claims never become CODE memory
  - failure semantics（card stage 14）: missing store → EMPTY_MEMORY（graph continues）; corrupt store → MEMORY_STORE_INVALID（fail-closed, never silent）; single-candidate rejection → structured status（write-back-only failure, closeout unaffected）; a claim of persisted knowledge is never made when the write failed
  - performance gate（card stage 16）: write-back cost bounded（per-write ms-class; duplicate retry near-zero no-op; conflict surfaces without growth; no-write baseline has zero added cost — write-back is opt-in）

  - repeated closeout / duplicated delivery → no duplicate trusted record
  - HOLD graph → execution history only, no unproven CODE truth

21. Known Risks and Limitations
================================================================================
  - CODE write-back requires an independent-review PASS + evidence identity — graphs without a review agent never write CODE memory（conservative by design）
  - SUPERSEDED validity maps to INVALIDATED（the schema has no SUPERSEDED validity status）— lineage is preserved via the SUPERSEDES relationship + lifecycle history
  - verification durations remain caller-provided（COST-1 known limitation）
  - store growth bounded by rotation; compaction deferred
  - no automatic CONFIRMED memory（Controller authority required — out of CBM-4 scope）
  - no silent conflict resolution（conflicts always surfaced; lifecycle transitions require evidence）
  - no vector/embedding/cloud memory（deterministic lexical + scope + identity only）
  - no self-evolution / adaptive routing / automatic token optimization
